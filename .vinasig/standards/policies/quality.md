# Source quality and dependencies

- QUAL-001 MUST use strict type checking where the stack supports it. For TypeScript enable strict, noUncheckedIndexedAccess and exactOptionalPropertyTypes. For JavaScript use JSDoc with allowJs/checkJs/noEmit when appropriate. Do not rename an existing JS project just to apply the policy. Validate framework-generated types with that framework's official checker.
- QUAL-002 MUST lint new applicable code with zero unexplained warnings. Use typed ESLint strictTypeChecked when a type project exists, Stylelint on actual CSS, and HTML-validate on HTML or generated HTML. JSX, Vue and Astro templates need their own adapters. Do not parse them as plain HTML. Use one formatter. Configuration presets in this repository are tested starting points, not a claim of zero defects.
- QUAL-003 SHOULD test functions, integration boundaries, authorization and critical user flows according to risk. New source and new behavior should have failure cases. Keep a legacy adoption inventory, non-growing defect baseline, explicit exceptions and a dated tightening plan. Never silently disable a rule to make adoption pass.
- DEP-001 MUST verify newly selected dependencies against an official registry/release, use current stable compatible versions, and record the lookup date, latest, selected, runtime/peer compatibility and migration blockers. Lock resolved dependencies. Existing unrelated tasks do not authorize broad major upgrades.
- DEP-002 MUST pin runtime, package manager, MCP packages and CI actions reproducibly. No floating `@latest` in normal execution or CI. Use one update bot that opens reviewable proposals. Do not auto-merge major/security-sensitive changes. Select a supported runtime, not the numerically largest release.

See the source/tool registry for the 2026-10-03 compatibility review. TypeScript 7.0.2 is latest, but the verified typescript-eslint 8.71.0 peer range excludes it. The tested bundle uses 6.0.3 until a reviewed compatible update. Node 24.21.0 and npm 11.19.0 are the pinned verification toolchain; minimum consumer runtime support remains Node 24.19.0. Node types follow runtime major 24 rather than latest major 26.

Security reviews combine dependency/secret checks with code-specific input validation and server-side authorization tests. Use the official [OWASP Application Security Verification Standard](https://owasp.org/projects/asvs) for relevant controls; pin its version and requirement IDs in a scoped audit. No browser audit replaces authentication tests, recovery/rollback, monitoring or a scoped security review. Telemetry and session replay are product decisions with privacy consequences.
