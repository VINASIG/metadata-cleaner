# Cleaner workflow review

Scope is the existing Metadata Cleaner checkout and the reported Clear button color and buried removal action. The review also covers the immediately related selection, completion, download and reset states. Parsing, byte-preserving surgery, dependencies, shared chrome, sibling repositories and publishing are outside the implementation change.

## Research and product decisions

- [Carbon button guidance](https://www.carbondesignsystem.com/building-blocks/core/components/button/guidelines) distinguishes the main action from lower-emphasis alternatives and identifies danger variants for actions that discard data. Apply those roles using existing VINASIG semantic tokens. Keep blue for creating the cleaned image, use a red outline for discarding session data, and reduce replacement and repeat-processing emphasis.
- [WCAG 2.2 focus not obscured guidance](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) identifies sticky content as a possible obstruction to keyboard focus. Keep the action toolbar in normal document flow at every viewport size, following the owner's preference, so it cannot cover focused controls or other cards.
- The ordinary task is choosing an image, reviewing or accepting the default selection, creating a new image and downloading it. Put these actions before the optional original inspection report. Retain every inspector feature and whole-block choice.
- Zero selected blocks is an intentional copy operation already supported by the parser. Preserve it and explain that metadata remains. Zero removable blocks also offers a copy, without irrelevant selection controls or a misleading removal label.
- Successful completion promotes download and demotes repeat processing. Keep file-name validation local to the field and return keyboard users to file selection after clearing.

These are a source-informed interface review and observed automated interactions. They are not participant research, measured conversion improvement or a real-device study.

## Verification record

The new workflow regression runs against the built artifact in Chromium, Firefox and WebKit. It also invokes `inspectUiContract` with explicit icon and field-error inventories. Existing source, unit, build, browser, shared-chrome and preference checks remain required. Lab loading measurements use three mobile and three desktop runs per language before and after, with matching browser/throttling settings. Raw data is retained in `output/ux-2026-10-08/lighthouse`.

Final results and the visually opened image inventory are recorded in `output/ux-2026-10-08/verification.json`. Physical devices, screen readers, independent agent trials, participant validation, field performance and deployed changes are not run in this local change. Publication requires the owner's authorization under the existing workflow.

## Owner feedback follow-up

The owner reported the download button touching the technical-details divider and the action card following the viewport while dragging the scrollbar. Before this follow-up, the desktop download-to-divider gap measured zero pixels. The choices card now precedes the action card, and all sticky positioning, toolbar-height tracking and related focus-scroll interception are removed. A one-rem margin before technical details separates the divider from both the download controls and preview.

Regression checks assert section order and the toolbar's unchanged document position after scrolling at desktop, mobile, breakpoint-neighbor, short and enlarged-text layouts. Completed outputs retain at least 16 pixels before the divider. Follow-up captures and reports are stored separately in `output/ux-spacing-2026-10-08` so the initial verification record remains available.
