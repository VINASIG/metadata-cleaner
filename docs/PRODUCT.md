# Metadata Cleaner

Remove optional metadata from one JPEG, PNG, WebP or GIF at a time. Inputs stay in browser memory. There is no upload API, telemetry, analytics, URL retrieval or remote proxy. A restrictive production CSP blocks network connections and form submission. Static page and asset requests still reach the hosting provider. Theme preference is the only local-storage value.

Every removable container block is selected by default. Choices remove whole blocks rather than editing individual EXIF fields, which can share offsets, proprietary data and thumbnails. A user can keep selected original blocks. The output filename defaults to image plus the detected extension to avoid carrying identifying original names. No author or camera identity is invented. Required display EXIF is reconstructed from an allowlist of orientation and documented color-space hints, without retaining original pointers, MakerNotes or padding.

The application removes APP metadata, comments, text, timestamps, editing/resource blocks, optional unknown chunks/extensions and trailing data. It retains compressed scans and frame data, palettes, transparency, animation timing/loops, decoder tables, necessary display aspect ratio and color profiles. ICC profiles are retained intact to avoid unverified color-transform changes. They may contain descriptions or identifiers. The report exposes this retained category. The tool cannot promise absolute anonymity or a universally minimal file size. It does not alter pixels, sensor fingerprints, steganography, faces, text, visible watermarks or visual locations.

JPEG JFIF is rebuilt without a thumbnail and with neutral density except a required non-square pixel ratio. EXIF is reduced to display-only data where needed. WebP RIFF lengths and metadata feature bits are repaired. PNG CRCs are checked and recomputed only for replacement metadata. GIF rendered plain text is display content and stays. Multiple-image MPF, JPEG JUMBF, recognized HDR gain maps, unknown critical PNG chunks and unknown animated WebP frame chunks are rejected rather than removing meaningful content. HEIC, AVIF, TIFF, raw images and JPEG XL are reader-only formats.

Before returning an output, the parser rereads it and compares every compressed image payload against the original, byte for byte, as well as dimensions. SHA-256 values give the user a readable payload integrity record. These values verify preservation, not anonymity. The output report lists retained and removed categories. File names, MIME hints and browser lastModified are shown separately from embedded metadata.

The full-width inspector groups image metadata, normalizes ExifReader tag records and removes PNG compatibility aliases. It shows an original-image preview, a compact overview, original tag paths/raw values and supported C2PA recorded actions. C2PA claims in PNG caBX are inspected through bounded JUMBF/CBOR/JSON parsing and selected for whole-block removal by default. C2PA signatures and certificate trust are not verified. Generic JUMBF does not imply Content Credentials. Unsupported compressed stores and CBOR structures produce partial warnings. JPEG JUMBF remains an explicitly rejected cleaner format. This release improves inspection and presentation without changing the byte-preserving surgery algorithm.

Users can switch between the original and processed metadata without rereading the input. JSON and copied reports reflect the selected view. Technical fingerprints are marked as calculated data. Binary fields show their byte length and a 256-byte hexadecimal preview. Inspection is bounded to 5000 fields, 8192 characters per value and 8 MiB of C2PA metadata. Repeated required image-data blocks are aggregated in a closed disclosure, with individual offsets retained in the JSON report.

The maximum file size is 100 MiB. Workers have a 20-second timeout, terminate on new work/reset/navigation and cannot update a stale revision. Container blocks, EXIF traversal and displayed tag counts are bounded. Image previews are limited to 40 million declared pixels. Metadata text uses textContent. No embedded URL, thumbnail or script is fetched or executed. The application reads one file at a time, supports explicit file selection, drag/drop and paste events, and does not poll the clipboard. Downloads and JSON export require explicit actions.

Root is Vietnamese and /en/ is English. Both themes reuse VINASIG tokens and shared chrome. Controls are a native file trigger, buttons, styled checkboxes, text/search inputs and disclosures. Select, date/time, color and range controls are not applicable. Details, group filters and search remain keyboard operable. JavaScript-unavailable file controls stay disabled with a visible explanation.

The three metadata tools share the same ordered Reader, Cleaner and Editor navigation cards, with a decorative Lucide icon, purpose, localized destination and non-link current-page state. The shared identity header and footer remain byte-preserved. Reports render up to 25 fields per page with native first, previous, next and last buttons above and below the results. Searching includes all parsed fields and raw values, group changes and replacement files reset pagination, and explicit JSON exports include the complete parsed report independently of the active page or search. Sparse reports need no pagination controls. Empty search results have a distinct message.
